# 验真与检索配方

## 证据强度三级

| 级别 | 什么算 | 怎么用 |
|---|---|---|
| 强 | 两个以上独立来源（非互相转载）+ 可核数字/档案 + 因果链说得出 | 可以作为论据 |
| 中 | 多源，但因果模糊（分不清个人功劳还是时势） | 可以用，要写「可能」 |
| 弱 | 单源、传说、后世附会、口述回忆 | 只能当类比，必须写明 |

## 红旗清单（见到就降级，多半是假史）

- 数字太整齐：十万人、三千万两、翻了十倍
- 对话像剧本：「他当时说：'……'」——史书极少记原话
- 名人语录查无出处（曾国藩、洛克菲勒、稻盛和夫、乔布斯 是重灾区）
- 年代错位：人物卒年早于事件年
- 来源全是自媒体/公众号/短视频文案，且彼此抄同一句
- 「据说」「相传」「有记载称」后面跟不出任何书
- 同一个故事漂在五个不同年代、不同人名下（典型民间故事漂移）

## 查证动作

1. 搜「人名 + 事件 + 年份」，看有没有百科、论文、出版社书评、新闻档案
2. 英文案例查**原语言拼写**，别用中文译名反查，译名往往对不上
3. 追原始出处：引用 → 书 → 页码。断在某一环就标「转引」
4. 数字冲突时取**多源区间**，不取最戏剧化的那个

## 检索配方

先换词，再搜：把行业词换成**结构词**（留不住人 → 复购 / 用户为什么离开 / 人为何退出集体）。

- 中文：`<结构词> 古代 如何解决`、`<结构词> 典故`、`<人名> <做法> 记载`、`<朝代> <事件> 复盘`
- 英文：`history of <problem>`、`how did <industry> solve <problem>`、`<company> <problem> case study`
- 反例：`<做法> 失败`、`why <approach> failed`、`postmortem <project>`
- 跨域：把结构词塞进反差大的行业（军事→教育、宗教→商业、生态→组织、医学→管理）

## 取材偏好

- 有具体人、具体时间、具体数量的记载 > 概述
- 当事人自述、档案、一手复盘 > 二手总结
- 案例成对出现（一个成功一个失败）> 只有成功
- 案例的年代尺度跟着问题走：战争与制度看百年，产品与渠道看五年
